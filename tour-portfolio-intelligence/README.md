# Tour Portfolio Intelligence (load factor analytics mockup)

A clickable front-end mockup of a load factor analytics dashboard for a tour operator running river cruises and escorted land tours. It is built for a prospect demo.

> **Everything here is sample data.** There is no backend, no auth and no real company data. Tours, departures and figures are generated by a deterministic generator with a fixed seed, so the numbers are identical on every run.

## Run it

Requires Node 20.9 or later.

```bash
cd tour-portfolio-intelligence
npm install
npm run dev          # http://localhost:3000
```

Production build:

```bash
npm run build && npm start
```

Lint and typecheck: `npm run lint` and `npx tsc --noEmit`.

## Stack

Next.js 16 (App Router) · TypeScript · Tailwind CSS v4 (layout only) · **Fluent UI React v9** (`@fluentui/react-components`, `@fluentui/react-icons`) · Recharts 3.

The UI follows Microsoft's Fluent 2 design system. The component mapping, tokens and setup notes are in [`design-system/MASTER.md`](design-system/MASTER.md).

## Screens

| Route | Screen | What it shows |
|---|---|---|
| `/` | Portfolio overview | KPI cards with year-over-year change (avg load factor, % departures above break-even, departures cancelled, cancellation and rebooking cost). A load factor trend chart (by year or quarter, total or split by type) with a break-even reference line. Portfolio health by status. "Needs attention" and "Reliable performers" lists. |
| `/tours` | Tour comparison | One row per tour. Each year's load factor is a heatmap cell (red below break-even, amber within 5 pts, green above). Also trend arrow, departures run vs cancelled, cumulative margin and an auto-assigned status badge. Sortable, searchable, filterable by status. `?status=Rework` preselects a status. |
| `/tours/[slug]` | Tour detail | Load factor by year against break-even. Departure-level chart of booked pax vs break-even vs capacity. Per-departure margin and cancellation cost table. An "AI insight" card with a plain-English summary and recommendation. |
| Side panel | Ask the data (demo) | A chat-style panel opened from the header. It offers five suggested questions with canned answers (text plus a chart or table) computed from the sample data. Free text gets a polite placeholder reply. The panel is clearly labelled as a demo. |

Global filters (year range, region, tour type) sit in a sticky bar under the header. They live in a React context in the root layout, so they persist across screens. They are also saved to `localStorage`, so they survive a refresh. Layouts work down to tablet width (about 768px).

## Data model

Defined in `src/data/types.ts`.

```ts
Tour {
  id, slug, name,
  region: "Rhine" | "Danube" | "French Rivers" | "Douro" | "Western Europe" | "Central Europe"
        | "Mediterranean" | "British Isles" | "Scandinavia" | "North America Fall Foliage",
  type: "River cruise" | "Escorted land tour",
  durationDays, firstYear, pricePerPax
}

Departure {
  id, tourId, tourName, region, type,
  date, year, season,
  capacity,          // contracted cabins / seats
  breakEvenPax,      // pax needed to cover contracted cost
  bookedPax,         // at cancellation if cancelled; current bookings if upcoming
  revenue,           // 0 if cancelled
  contractedCost,    // full cost if operated/upcoming; attrition fees if cancelled
  status: "operated" | "cancelled" | "upcoming",
  rebookingCost,     // cost of moving guests if cancelled
  cancellationReason?: "Below break-even" | "Low water levels"
}
```

### Metric definitions (`src/lib/analytics.ts`)

- **Load factor** = booked pax ÷ capacity. **Break-even load factor** = break-even pax ÷ capacity.
- Cancelled departures count at the bookings they held when cancelled. Cancelling weak dates therefore does not flatter the load factor.
- A **tour-year is below break-even** when its total booked pax is less than its total break-even pax.
- **Margin** = revenue − contracted cost − rebooking cost. Upcoming departures show projected margin at current bookings.
- **Status badge**:
  - Retire candidate: below break-even in 3 or more years.
  - Rework: below break-even in 2 years.
  - Watch: below or within 5 pts of break-even in the latest year, or declining with less than 10 pts of headroom.
  - Keep: everything else.
  Statuses are recomputed for the selected year range.

### Mock data (`src/data/seed.ts`)

There are 40 tours and about 1,300 departures across 2023 to 2026, with 4 to 12 departures per tour per year. The demo's "today" is fixed at **5 Oct 2026**: later departures are `upcoming`. A mulberry32 PRNG is seeded per tour from a fixed seed and a hash of the tour name, so adding a tour does not shift the others.

Each tour has a hidden profile that shapes demand so the dashboard tells a story:

- **6 consistently strong tours**, for example Swiss Alps & Lakes, Paris to Normandy on the Seine and Douro Valley Wine Route.
- **5 retire candidates.** Four are chronically below break-even (Lower Rhône & Camargue, Danube Delta Explorer, Scottish Islands & Lochs, Atlantic Canada Foliage Circuit). The fifth, Rhine & Moselle Explorer, has a seasonal split: spring fills and autumn does not.
- **Risers** (for example Norwegian Fjords & Rail and Ireland's Wild Atlantic Way) and **fallers** (for example Grand Tour of Germany and Benelux & Rhine Valley).
- A **low water dip on the Rhine and Danube from August to November 2026**. Some departures are cancelled for low water and later ones have soft bookings. Switch the trend chart to "By quarter" and filter to Rhine or Danube to see it.

## Plugging in real data later

All screens read data through two layers:

1. **`src/data/seed.ts`** exports `TOURS` and `DEPARTURES`. Replace the generator with a loader that returns the same shapes. Typical sources:
   - the reservation system for bookings, departure dates and status;
   - the contracting system for capacity, break-even and contracted cost by component (ship, hotel, coach);
   - finance for revenue, attrition fees and rebooking cost.

   A nightly extract into a warehouse table with one row per departure is the simplest fit.
2. **`src/lib/analytics.ts`** holds pure functions (`aggregate`, `summarizeTour`, `needsAttention`, `tourInsight`, …) with no React dependency. They can run unchanged in a server component or API route over the real extract. At larger volume, push the aggregations down into SQL.

Further steps for production:

- Swap the client-side `DEPARTURES` import for server-side fetching.
- Add auth.
- Replace the rule-based "AI insight" and "Ask the data" answers with an LLM agent that has query access to the departure table.
